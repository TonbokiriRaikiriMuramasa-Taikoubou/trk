# 🛡 セキュリティ（脆弱性の洗い出しと、その後の守り）

trk! は **サーバーを持たない** ブラウザ音ゲーです。アカウント・広告・行動分析はなく、曲も書斎の本も端末の外へ出ません。
そのぶん攻撃面は「**他人が作ったファイルを読み込むところ**」「**ブラウザに入ってくる他人のコード**」「**端末に貯まる私物**」に集中します。
この文書は 2026-10-06 に **色々な側面から一度しっかり洗い出した** 結果と、そこで塞いだ穴、残した仕様、これからの推奨をまとめたものです。

- 自動で見張るのは `tools/check-security.mjs`（`npm run check` に含まれる）。
- 仕様として残したものは「**なぜ残すか**」まで書いてあります。**見つけた穴は隠さず、直したうえで記録する**のがこの文書の方針です。

---

## 1. 前提（trk! のなりたちと、守るべきもの）

| 項目 | 中身 |
|---|---|
| 配布 | 静的ファイル（GitHub Pages）。ビルド無し。Android は Capacitor の WebView に入れた同じ一式 |
| 保存 | `localStorage`（設定・記録・お気に入り・アドオン）+ IndexedDB（パック・曲・VRM/MMD・書斎の本） |
| 外部通信 | **同一オリジンの取得のみ**＋VRM/MMD を使うときだけ jsDelivr CDN（three.js 系） |
| サーバー | 無し。trk! へ送信する処理は無い（送る機能を作らない） |
| 守るべきもの | ①端末内の私物（書斎の本・画像・曲・スコア・設定）②「入れたつもりの無いコード」を動かさないこと ③壊れないこと（データ消失・フリーズ） |

## 2. 信頼の境界（どこまで信じて、どこから検証するか）

| 入力 | 扱い | 検証 |
|---|---|---|
| 本体のコード（このリポジトリ） | **信頼する** | GPL / レビュー / `npm run check` |
| jsDelivr の three.js・three-vrm・three-mmd-loader | **信頼している（要監視）** | バージョン固定。中身は trk! の管理外 → §6 の推奨 |
| 共有ファイル：パック `.stpack`、譜面 `.shadow-taiko.json`、プレイリスト `trk-playlist`、エフェクト `trk-fx`、TVスキン `trk-tvskin`、スキン `.skin.json`、⭐ `trk-favs`、記録 `shadow-taiko-records`、公認 `verified.json` | **信頼しない** | 形式・範囲・https・パス・容量を検証してから使う |
| 🧩 アドオン（`.js` / `.trk-addon`） | **入れた人の責任**（＝ページ内でフル権限のプログラム） | 同意の文言・サイズ上限・安全モードでの停止 |
| 端末の保存（localStorage / IndexedDB） | **ユーザーの私物だが、改ざんされうる** | 読み込み側で毎回かたちを整える |
| URL（`?safe=1` `?reset=…` `?tv=…` `#…`） | **誰でも作れるリンク** | できることを限定し、危ないものは確認や明示を要求（§5） |
| ファイル選択・フォルダ共有 | ユーザーが明示的に選んだもの | **読み取り専用**（書き込み API 不使用） |
| 覚えてあるフォルダのハンドル（IndexedDB `shadow_taiko_library` の `share` / `dir`） | 便宜のため保存するが、**ページ内コードから読める**（＝アドオンも読める） | 「🚫 共有をやめる」で両方削除。⚠ 権限の取り消しはブラウザ側 |

## 3. 洗い出しのやり方

1. **静的走査**：危ない書き方（`eval` / `new Function` / `document.write` / `srcdoc` / 素の `innerHTML` / `target=_blank` の rel 漏れ / `href` への直代入）を全部数える。
2. **検証コードの読み合わせ**：共有ファイルを読む関数を、形式・型・範囲・パスの4点で確認。
3. **動的確認**（jsdom ハーネスをリポジトリ外で実行）：`javascript:` の名刺 URL、`__proto__` 入り設定、宣言サイズを偽った ZIP、安全モード、リセット経路などを実際に流す。
4. **自動の見張り番**：洗い出しで見つけた「守り」を `tools/check-security.mjs` に固定し、`npm run check` で毎回検査（戻ってきたら FAIL）。

## 4. 見つけたもの

重要度は **高**＝他人のファイルを入れて数クリックで任意コード実行や持ち出し／**中**＝条件付きでコード実行・データ消失・フリーズ／**低**＝自分で操作したときだけ・表示だけ／**情報**＝仕様の明確化。

### ✅ 検証して「問題なし」と確認したもの（疑いを1つずつ潰した記録）

| 疑い | 調べ方 | 結果 |
|---|---|---|
| 📚 書斎の**パス・トラバーサル**（`../` で端末のファイルを読む／書く） | `relativePath` → `stableId` → IndexedDB の流れを追い、書斎が**ファイルシステムや URL に path を渡す箇所が無い**ことを確認（唯一の `img.src` は許可リスト画像のブロブ URL）。`../../../../etc/passwd.txt` を実際に取り込み | **問題なし**。path は「本の見出し・検索対象」と IndexedDB のキー（ハッシュID）にしか使われない。書き込みはメモの書き出しだけで、ファイル名からは `\ / : * ? " < > \|` を除去。実測で外部への読み書きも発生しない |
| 書斎の**ファイル偽装**（`.txt` の中身が HTML/JS で、HTML として描画される） | 本文の描画経路を追い、`.html` / `.js` / `.md` / `.csv` / `.json` を実際に取り込んで開いた | **問題なし**。本文は `createTextNode` / `textContent` だけで組み立てられ、**マークダウンのレンダラも HTML 解釈も存在しない**（ソースがそのまま文字として見える）。`<script>`・`onerror`・`javascript:` リンクは実行も生成もされない |
| 書斎の本文に**スクリプトが混ざる**（青空文庫ルビ経由） | ルビ解析の出力を全部 DOM へ通す箇所を確認 | **問題なし**。`{ruby, reading, text}` はすべてテキストノード（`<rt>` も `textContent`）。HTML として解釈される経路は無い |
| **CDN のサプライチェーン**（three.js / three-vrm / three-mmd-loader を jsDelivr から読む） | import map の URL・`import()` の呼び出し箇所・Service Worker のキャッシュ条件を確認し、**モジュールグラフ全体（94ファイル・3.60MB）の SHA-384 を記録**して検証する道具を作った（`npm run check:cdn`）。あわせて npm の公開タール玉と突き合わせる `npm run check:cdn:npm` も用意 | **固定は完全**（`@0.180.0`／`@3.5.5`／`@0.8.4` のような完全固定のみ。範囲指定・`latest` は無し）。**起動時には一切読まない**（VRM／MMD を使い始めたときだけ動的 import。`?safe=1` では VRM・MMD とも `skin` に戻すので CDN を触らない）。Service Worker は**クロスオリジンをキャッシュしない**ので、汚染が端末に残る経路も無し。未使用だった `@pixiv/three-vrm-core` の import map 項目を削除（1つぶん供給網が縮小） |
| 書斎の**画像**が HTML／SVG だった場合 | 許可リストと描画先を確認 | **問題なし**。許可リストは `jpg/jpeg/png/webp/gif/avif/bmp` のみ（**SVG は除外**、check-study-room が見張り）、描画は `<img src=blob:>` だけ（`<iframe>`／`<object>` は不使用） |

### 逆に、すでに固かったところ（回帰させない）

- `eval` / `new Function` / `document.write` / `srcdoc` は **0 件**。`innerHTML` は結果画面の1か所だけで、**すべて `esc()` を通した**テンプレート。
- 共有ファイルの検証が各形式にそろっている：パック（形式名・`../` と絶対パスの禁止・拡張子の許しリスト・種類ごとの容量上限）、スキン（色は `#rrggbb` のみ、フォント等は許しリスト）、TVスキン（数値の範囲と飾りの許しリスト）、譜面（形式・ノート数 50,000 上限・有限値・レーン0/1・楽曲長との整合）、公認リスト（書式・https の作者リンク・X のID形式・SHA-256 の指紋照合）、エフェクト（種類と範囲）。
- プレイリストの入手先リンクは **https 限定＋開く前に確認**（`window.open` は `noopener,noreferrer`）。
- アドオンのサンプル取得は**同一オリジン**（`js/addons/example.js`）のみ。遠隔からコードを取りに行く経路は無い。
- Service Worker は**同一オリジン・GET・basic 応答だけ**をキャッシュ（他人の応答や不透明応答を混ぜない）。
- ファイル/フォルダ選択は**読み取り専用**（`mode:"read"`）。`postMessage` の受信口は無し。
- 書斎・曲・パックの取り込みには容量・件数の上限があり、本文は `textContent` で組む（HTML として解釈しない）。

## 5. 仕様として残したこと（と、その理由）

1. **アドオンは「入れた人の責任」**：ページの中のフル権限で動くプログラムです（ブラウザ拡張やユーザースクリプトと同じ考え方）。だから
   - 入れるのは**ファイル選択（または同梱の `js/addons/○○.js`）だけ**。パック・プレイリスト・譜面などの共有ファイルから**勝手にインストールされる経路は無い**。
   - `?safe=1` では**読み込まない**（入れたものは消えない）。
   - 512KB の上限。入れたアドオンは一覧から**オフ／削除**できる。
2. **スコアはローカルの記録**：端末を持っている人は書き換えられます。「書き換え不可能なランキング」ではないので、そこを前提にした機能は作りません。
3. **共有プレイリスト（他人から受け取るファイル）で起きること・起きないこと**：楽曲ファイルも譜面も含まず、**コードも実行しない**（JavaScript は一切入っていない）。相手ができるのは
   - 曲名・アーティスト名などの**見出しを偽ること**（あなたの手持ちの曲と同名にすると、その曲として表示される＝**なりすまし**。取り込むかどうかは自分で選べる）
   - コメント・タグ・投稿者名で**文章を表示させること**（いずれもテキストとしてのみ表示・長さ上限あり。HTML としては解釈しない）
   - **https のリンクを踏ませること**（開く前に必ず確認ダイアログ。§F-1/F-14 の関所つき＝フィッシングの可能性はゼロではない）
   - 大量の曲名を並べること（1000曲・タグ5個・フォルダ/プレイリスト数に上限）
   つまり**「だます」ことはできても、「コードを動かす」「あなたのファイルを読む」ことはできない**、が設計です。
4. **破壊的なリセット URL は即効**：`?safe=1` や `?reset=…` は「映像が変になった」「音が壊れた」ときの非常口なので、**ワンタップで効く**ことを優先しています（消えるのは設定だけで、記録・パック・書斎の本は消えません）。

## 6. これからの推奨（未実施・検討中）

1. **CSP（Content-Security-Policy）を meta で入れる**：`index.html` の先頭に、例えば
   `default-src 'self'; script-src 'self' blob: https://cdn.jsdelivr.net; connect-src 'self' https://cdn.jsdelivr.net; img-src 'self' blob: data:; media-src 'self' blob:; style-src 'self' 'unsafe-inline'; frame-ancestors 'none'`
   → ただし inline の `<script type="importmap">` とアドオンの `blob:` 読み込みがあるため、**import map を外部ファイル化＋ハッシュ/nonce 化**してからが安全です（壊すリスクがあるので段階的に）。
2. **three.js 系の自前ホスティング（vendor 化）**：`assets/vendor/` に固定版を置き、import map を相対パスに。CDN 障害・改ざん・オフラインの3つが同時に解決します（サイズ増とのトレードオフ）。**実測の大きさ：モジュールグラフ全体で 94ファイル・3.60MB**（MMDローダ＋アセット約3.0MB、three.js 本体 0.60MB＋GLTFLoader 0.11MB、three-vrm 一式 約0.5MB）。
   当面はこの順序を推奨：① 版を上げるときは必ず `npm run check:cdn`（§8）② 気になるときは `npm run check:cdn:npm` で npm 側とも突き合わせる ③ 腰を据えて移すなら自前ホスティング。
3. **破壊的リセットの確認**：`?reset=all` / `#reset=all` は「もう一度で確定」方式にする（緊急時でも2タップ）。
4. **アドオン同意の強化**：インストール時にコードの先頭をプレビュー＋「実行されます」確認、指紋（SHA-256）を保存して次回読み込み時に照合。
5. **`mobile-web/` から開発用文書を除外**（`docs/HANDOFF.md` など）。
6. **GitHub Actions の SHA 固定**（`actions/checkout@<sha>`）。
7. **ヘッダ系**：`Content-Security-Policy: frame-ancestors 'none'` や `Permissions-Policy` は配信側（Cloudflare Pages など）を挟む場合に設定。

## 8. CDN の中身を自分で確かめる（`tools/cdn-lock.json`）

trk! が CDN から読むモジュールは**94ファイル**あり、その全部の **SHA-384** を `tools/cdn-lock.json` に記録してあります。入口の `import()` から `import` の連鎖を辿り、WASM やテクスチャのような**実行時アセット**（`new URL("…", import.meta.url)`）まで含みます。

```
node tools/check-cdn.mjs               # CDN のいまの中身が記録と一致するか（ネットワークが要ります）
node tools/check-cdn.mjs --source=npm  # 同じグラフを npm レジストリのタール玉から読んで突き合わせる
node tools/check-cdn.mjs --list        # 何を読む予定かの一覧（サイズ付き）
node tools/check-cdn.mjs --update      # 版を上げるときだけ lock を作り直す
```

`CHANGED` が出たら、**版を上げた覚えが無い限り**その CDN の中身は信用しないでください。VRM／MMD を使わなければ、アプリのほかの部分は影響を受けません（起動時に読むことはありません）。`npm run check` は**ネットワークを使わない**ままにしたいので、この確認は別コマンド（`npm run check:cdn`）にしてあります。
